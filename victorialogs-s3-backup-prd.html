PRD · 内部运维工具

VictoriaLogs 不停机备份 / 恢复工具（S3 后端）

以「天分区」为单位，在 VictoriaLogs 持续写入的前提下把历史日志备份到 S3 兼容对象存储，并支持按指定日期在线回灌到原实例或新实例。交付物为单一 Go 二进制。

1. 背景与目标

VictoriaLogs 的数据以 UTC 天为单位落在 <storageDataPath>/partitions/<YYYYMMDD>，每个分区自包含。它是日志的唯一副本：一旦分区目录损坏、被误删，或实例所在磁盘故障，-retentionPeriod 到期前的数据将不可找回；同时，日志常常需要「比保留期更久」地留存以应对审计与故障复盘。

现有做法有两个明显缺口：一是只能整库停服冷拷贝，与「日志不能断」冲突；二是靠人工 rsync 到远端机器，缺少完整性证据、无法回答「2026-10-27 这份备份能不能用」。

产品决策与预期可观察结果：

  • 备份对象是分区而不是实例：按天可增量、可单独校验、可单天回灌。
  • 备份与恢复全程通过 VictoriaLogs 自带的分区管理端点完成，不重启进程，其余日期的写入与查询不受影响。
  • 完成判定可观察：运维能列出某天备份、看到文件数与字节数、校验通过，并在恢复后查询到该天数据。

2. 角色、场景与判定

角色职责与权限边界
SRE / 值班同学发起单天备份与恢复；只读查询备份清单；恢复属于高危操作，需显式确认。
平台研发部署二进制、配置 S3 凭据与定时任务、排查失败作业。

核心场景（P0）

  1. 日常备份：cron 每日凌晨把「昨天」的分区备份到 S3，失败需告警。
  2. 按天恢复：某天数据被误删或损坏，运维指定日期在线回灌，无需停服。
  3. 备份可信：审计前能证明某天备份完整（清单 + 校验）。

触发：定时任务或人工执行一次 CLI 命令。完成条件：备份侧出现带 manifest 的提交记录且校验通过；恢复侧目标日期数据可被查询，且实例未重启、其他日期无影响。

4. 核心模型与术语

术语定义
分区（Partition）partitions/YYYYMMDD（UTC 日）。备份与恢复的最小单位，内部文件不可变。
快照（Snapshot）VictoriaLogs 为某分区生成的硬链接视图，秒级、几乎不额外占空间。仅备份期间存在，用完即删。
备份单元（Backup Unit）某节点某一天在 S3 上的一组对象：files/ 下的数据文件 + 一个 manifest.json。
提交点（Commit）manifest.json 上传成功即为提交。无 manifest 的前缀一律视为未完成备份，不可用于恢复。
节点（Node）单机部署时即实例本身；集群部署时为每个 vlstorage。备份仓库以节点为命名空间。
恢复点（Restore Target）被替换的目标分区目录；替换前可保留为 .replaced-<ts> 以便回滚。

仓库布局（格式版本 v1）

s3://<bucket>/<prefix>/v1/
  <cluster>/<node>/<YYYYMMDD>/
    manifest.json          ← 提交点，最后写入
    files/…                ← 分区内相对路径原样保留

选择「原样保留相对路径」而非自定义归档格式：恢复时无需任何转换，也不依赖版本化的打包格式；单文件即不可变单元，天然支持文件级断点续传与并行。

分区与作业状态

对象状态允许的迁移
分区present / detached / replaced / attachedpresent → detached → replaced → attached；任一失败步骤必须回退到 present
备份作业snapshotting / uploading / committing / committed任意中间态 → failed / abandoned；仅 committed 可被恢复复用

5. 功能需求

FR-01 备份（Backup）P0

目的
把指定日期分区在不停机前提下完整落到 S3，并留下可验证的提交记录。
触发
backup --date 2026-10-27、backup --from … --to …、backup --latest 3（最近 N 个已完整落盘的天），无参数时默认「昨天（UTC）」。
前置校验
① VictoriaLogs 端点可达；② 目标分区目录存在且非空；③ 本机对该分区有读权限；④ S3 桶可写（一次 HeadBucket/探测写）；⑤ 本地无同分区作业锁。
处理规则
1) 调分区快照接口创建快照并记录返回路径；2) 遍历快照目录，按相对路径逐个上传到 files/；3) 全部对象上传成功后写入 manifest.json（提交）；4) 无论成功失败，最终删除快照。
结果
打印摘要：分区、文件数、总字节、耗时、跳过的已存在对象数；S3 上出现可恢复的备份单元。
边界
分区不存在 → 退出码 4；当天分区仍在写入 → 允许，但提示「快照仅包含已落盘数据，最近约 1 秒缓冲不在其中」，并提供 --force-flush 先落盘；已存在提交 → 按 --if-exists=skip|replace（默认 skip）；某文件上传失败 → 重试后仍失败则整体失败，且不写 manifest。

FR-02 快照生命周期P0

目的
保证备份读取的是一致视图，同时绝不让快照长期占盘。
规则
快照仅在作业内存在，作用域为单个分区；作业结束（含异常退出）必须清理。进程被强杀时来不及清理，因此每次作业启动前先清理「孤立快照」（按快照存在时长阈值判定）。
约束
不提供「长期保留快照」作为常规用法；--keep-snapshot 仅供排障，且必须在摘要中显式告警其占用的空间不会随保留策略释放。

FR-03 上传、断点续传与幂等P0

目的
在跨可用区/跨云的网络条件下，把「几十 GB、数万文件」稳定传完，中断后不从头再来。
处理规则
① 文件级并发（默认 8，可配）；② 单文件超过阈值走分段上传；③ 上传前对目标对象做 HEAD，已存在且大小一致则跳过（文件不可变，具有天然幂等性）；④ 单文件失败按指数退避重试，重试耗尽才判定作业失败；⑤ 全部完成后才写 manifest。
结果
重复执行同一天备份，除 manifest 时间戳外不产生新的数据对象。
边界
对象存在但大小不一致 → 视为残缺，重新上传覆盖；同一 cluster/node/date 存在并发作业 → 后启动者拒绝（退出码 6）。

FR-04 在线恢复指定日期P0

目的
把某一天的备份回灌到运行中的实例，且不影响其他日期的查询与写入。
触发
restore --date 2026-10-27 --yes（可加 --node / --cluster / --dry-run / --on-existing=keep|replace）。
处理规则
1) 读取 manifest 并校验备份单元完整性；2) 下载全部文件到数据目录之外的临时目录（同一文件系统，便于原子 rename）；3) 逐文件校验大小（--deep 时校验哈希）；4) 若目标分区存在则 detach；5) 将临时目录 rename 为 partitions/YYYYMMDD，旧目录按 --on-existing 保留或删除；6) attach；7) 可选冒烟查询该天是否有数据返回。
结果
目标日期可查；实例进程未重启；其余日期无变化。摘要给出替换的文件数、字节数与耗时。
边界
目标分区为「今天」→ 强制二次确认并告警：覆盖后恢复点之前的实时日志会丢失；磁盘剩余空间不足分区大小 + 余量 → 前置失败（退出码 6），不开始下载；节点名与 manifest 不一致 → 默认拒绝，需 --allow-node-mismatch。
失败回滚
detach 之后任一步失败：若尚未替换，直接 attach 原目录；若已替换，则回滚旧目录后再 attach。回滚失败必须原样输出人工处置步骤（含具体路径与命令），不得只报「失败」。
权限
恢复属高危操作，非交互环境必须显式 --yes；交互环境需二次确认并回显将替换的路径。

FR-05 清单查询与校验P0

目的
回答「某天有没有备份、多大、可不可信」。
规则
list 按节点列出已提交备份（日期、文件数、字节数、提交时间、工具版本）；verify --date 校验对象存在性与大小；verify --date --deep 下载并比对哈希。
结果
表格输出 + 稳定的退出码；任意不一致项需逐条列出（对象键、期望值、实际值）。

FR-06 保留清理P1

规则
gc --keep-days 30 或 gc --before 2026-01-01，仅删除已提交且满足条件者；顺带清理无 manifest 的未完成前缀。默认 --dry-run 列出将删对象，需 --yes 才真正删除。

FR-07 集群多节点P0

规则
仓库路径强制包含 cluster/node；单机部署可用固定值。备份可对多节点逐个执行（失败隔离，单节点失败不阻断其他节点，但整体退出码非 0）；恢复必须明确目标节点，不做「自动找节点」。
理由
集群下数据按流分散在各 vlstorage，只有同一节点的备份才能拼回完整的一天。

FR-08 配置与凭据P0

规则
配置来源优先级：命令行 flag > 环境变量（VLB_*）> 配置文件。必须包含：VictoriaLogs 地址与分区管理鉴权、数据目录、S3 端点/桶/前缀/区域/路径风格、并发与超时。凭据支持环境变量、共享凭据文件、实例角色三种来源。
安全
凭据不得出现在日志、摘要与错误信息中；配置文件权限不当（组/其他可读）时给出告警。

6. 共享规则与异常矩阵

提交点规则（唯一权威）

  • 只有 manifest.json 写入成功，备份才成立；list/restore 一律只认 manifest。
  • manifest 最后写入，内容包含全部对象的键、大小与哈希，因此它是「完整性声明」而不是目录清单的缓存。
  • 重新备份同一天且内容变化时，必须先上传新对象、写入新 manifest，再清理旧 manifest 中不再被引用的对象；不得先删后传。

时间语义

  • 所有日期按 UTC 解释；--date 只接受 YYYY-MM-DD。
  • 用户处于非 UTC 时区时，摘要中必须回显「本次操作对应 UTC 分区 YYYYMMDD」，避免选错天。

并发与锁

  • 同一 cluster/node/date 同一时刻仅允许一个备份或恢复作业，由本地锁文件保证。
  • 备份与恢复可并行在不同日期上执行；恢复同一节点不同日期时逐个执行（避免同时多次 detach 干扰排障）。

异常矩阵

情况行为退出码
VictoriaLogs 不可达 / 5xx指数退避重试后失败，提示检查地址与鉴权3
分区目录不存在明确报「该 UTC 日无数据」，不创建空备份4
S3 桶不存在 / 无权限前置失败，不创建快照6
上传中网络中断保留已上传对象，作业失败；重跑时跳过已存在同大小对象3
快照创建成功但上传失败必须清理快照并提示；失败清理需告警1
恢复时磁盘不足不下载任何文件，直接失败6
恢复中 attach 失败回滚到原目录并 attach；输出人工处置步骤1
校验大小/哈希不一致列出差异项，判定备份不可用5
用户取消确认不产生任何副作用7

7. 技术约束

类别约束
语言与产物Go（1.22+），CGO_ENABLED=0 静态链接，单文件二进制；目标平台 linux/amd64、linux/arm64。
运行依赖不依赖 rsync、aws-cli、Python 等外部程序；只使用 VictoriaLogs HTTP 端点与 S3 HTTP API。
VictoriaLogs 版本需支持分区快照创建/删除与 detach/attach 端点；最低版本 [TBD]，启动时探测并在不满足时拒绝执行。
存储兼容AWS S3、MinIO 及 S3 兼容端点；必须支持 path-style 寻址；不依赖 S3 Select、对象锁等高级特性。
一致性一致性只能来自分区快照；禁止直接拷贝正在写入的分区目录。
资源流式读写，单文件不整体载入内存；内存占用随并发数线性增长且有上限；恢复所需磁盘 ≈ 分区大小 × 1.1（含旧目录保留）。
网络只允许出站 HTTPS；支持代理环境变量；单请求超时与总作业超时可配。
权限最小集VL 侧：分区只读 + 分区管理端点；S3 侧：ListBucket、GetObject、PutObject、DeleteObject、HeadObject、分段上传相关权限。
安全不落盘明文凭据；恢复等高危操作需显式确认；日志脱敏。
规模假设单日分区典型大小与文件数 [Assumption, TBD]；设计目标为「数万文件 / 数十 GB」可稳定完成，需以实测校准并发默认值。

8. 工程规范

8.1 CLI 规范

vlogs-backup <command> [flags]

commands:
  backup   备份一个或多个日期分区
  restore  在线恢复指定日期分区
  list     列出已提交备份
  verify   校验备份完整性
  gc       清理过期/未完成备份
  version  输出版本与构建信息

常用示例：
  vlogs-backup backup --date 2026-10-27
  vlogs-backup backup --latest 3 --if-exists skip
  vlogs-backup backup --from 2026-10-01 --to 2026-10-07 --cluster prod --node vlstorage-0
  vlogs-backup restore --date 2026-10-27 --node vlstorage-0 --yes
  vlogs-backup list --from 2026-10-01 --format table|json
  vlogs-backup verify --date 2026-10-27 --deep
  vlogs-backup gc --keep-days 30 --dry-run
Flag适用命令默认说明
--vl-urlbackup/restore—VictoriaLogs 地址，必填或由配置提供
--data-pathbackup/restore—实例 -storageDataPath，恢复必须与运行实例一致
--cluster / --node全部default仓库命名空间
--concurrencybackup/restore8文件级并发
--if-existsbackupskipskip / replace
--on-existingrestorekeep旧分区保留为 .replaced-<ts> 或直接删除
--deepverify/restorefalse启用哈希校验（更慢）
--dry-run全部写操作false只打印将执行的动作
--yesrestore/gcfalse非交互确认
--json全部false输出机器可读结果，便于 cron 告警

8.2 manifest（v1）字段

{
  "format_version": 1,
  "cluster": "prod-logs",
  "node": "vlstorage-0",
  "partition": "20261027",
  "created_at": "2026-10-28T01:12:03Z",
  "snapshot_at": "2026-10-28T01:11:58Z",
  "vl_version": "v1.xx.x",
  "tool_version": "0.1.0",
  "file_count": 128,
  "total_bytes": 73400320,
  "entries": [
    { "path": "parts/xxxx/yyyy.bin", "size": 1048576, "sha256": "…" }
  ]
}

约定：entries[].path 为分区内相对路径，S3 键为 files/<path>；format_version 不兼容时拒绝恢复；entries 是完整性声明的唯一来源。

8.3 退出码

码含义
0成功
1未分类错误（含回滚失败）
2参数或配置错误
3远端不可达/网络失败（可重试）
4目标不存在（分区或备份缺失）
5校验失败（数据不一致）
6前置条件不满足（磁盘/锁/权限）
7用户取消

8.4 日志与输出

  • 结构化日志（log/slog），字段固定：ts、level、op、cluster、node、partition、phase、bytes、files、err。
  • 人读输出走 stdout，进度与告警走 stderr；--json 时 stdout 仅一行业务结果 JSON。
  • 任何失败必须给出「发生了什么 + 当前状态 + 建议下一步」，回滚失败需附具体命令。

8.5 Go 工程规范

  • 目录：cmd/vlogs-backup（入口）、internal/vl（端点客户端）、internal/s3store（对象存取与键布局）、internal/backup、internal/restore、internal/manifest、internal/config。
  • 所有外部调用必须带 context 与超时；重试集中在客户端层实现（指数退避 + jitter），业务层不重复写重试。
  • 错误必须包装上下文（fmt.Errorf("…: %w", err)），不得吞错；不用 panic 处理可预期错误。
  • 文件系统操作使用同分区 rename 保证原子性；禁止跨设备移动。
  • 测试：httptest 模拟 VictoriaLogs 端点覆盖快照/detach/attach 语义；S3 用 MinIO 或本地仿真实现做集成测试；回滚路径必须有专门的失败注入测试。
  • 质量门禁：gofmt、go vet、golangci-lint、单测覆盖率不设数字指标但核心回滚逻辑必须覆盖。

8.6 构建与发布

  • make release 交叉编译 linux/amd64、linux/arm64，产物命名 vlogs-backup_<version>_<os>_<arch>，同时生成 sha256sum。
  • 版本信息通过 -ldflags "-X main.version=… -X main.commit=…" 注入，version 子命令输出版本、commit、构建时间、Go 版本。
  • 发布说明必须包含仓库格式版本号；格式不兼容变更需提升 format_version 并提供读取旧版本的兼容期。

8.7 运维使用约定

  • 推荐 cron：0 2 * * * vlogs-backup backup --latest 1 --json，失败以非 0 退出码触发告警。
  • 备份仓库建议配置桶级生命周期仅做「归档到低频」，删除交给工具自身，避免 S3 生命周期与 manifest 语义冲突。
  • 恢复后必须执行一次 verify 与冒烟查询；.replaced-<ts> 目录在确认无误后手工清理。
